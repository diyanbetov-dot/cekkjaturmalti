5. CURRENT LIVE CORPUS CALL PATH
================================

Construction:

  Essentials/app.py
    -> MalteseCorpusScorer(...)
    -> spellchecker.corpus_scorer = corpus_scorer

Configuration today:

  SPELLCHECK_CORPUS_SCORING=false by default
  SPELLCHECK_CORPUS_SHADOW=false by default
  unigram=true
  bigram=true
  trigram=false
  max contribution=0.25

Only production call:

  _build_candidate_evidence_pool()
    -> CandidateEvidencePool.annotate_corpus(corpus_scorer)
    -> MalteseCorpusScorer.score_candidate(...)

The call passes no prev_word, next_word, or prev_prev_word. Therefore even when
enabled, production scoring is effectively unigram-only. The scorer can compute
left bigram, right bigram, and trigram components, but no live caller provides
the context.

The pool is reached only from late suggestion/evidence paths after many
correct_word and phrase-rule early returns. Instrumented required cases reached
it zero times. Corpus evidence currently mutates generic confidence rather than
remaining a separately diagnosable component in the final selection key.

The current scorer exposes one bounded total, not a structured result containing
unigram, left bigram, right bigram, trigram, before-cap total, after-cap total,
availability, fallback, and mode.


6. CURRENT LIVE BERTU CALL PATH
===============================

Construction:

  Essentials/app.py
    -> BertuReranker()
    -> spellchecker.bertu_reranker = bertu_reranker

Production selection caller:

  none

Only the offline evaluator and the reranker's own convenience method call
score_candidates(). The representative live requests recorded zero calls.

Current limitations:

  - lazy model loading has no explicit off/shadow/active mode;
  - sentence.split() is the default token alignment;
  - token_index is a whitespace-token index, not a source-span mapping;
  - only the first candidate subword is scored;
  - multi-token candidates, apostrophes, hyphens, punctuation, emojis, and
    contextual previous-sentence tails are not represented safely;
  - there are no per-request call/time budgets, winner-margin policy, cache
    diagnostics, overwrite history, or production failure status;
  - BERTu can return scores, but no authoritative selector consumes them.


7. SELECTORS THAT BYPASS CANDIDATEEVIDENCE
==========================================

1. correct_word early returns:
   negative copula, unique keyboard shortcut, special l' pass-through,
   dictionary/recognized surface, initial i-, fixed time expression, ta suffix
   gloss, glide collapse, and exact suffix matches.

2. Phase X/Phase Y:
   _phase_x_collect_candidates sets analysis.corrected and a priority candidate;
   _phase_y_basic_resolution returns a winner directly.

3. Article/preposition phrase rules:
   match_split_article, match_hyphenated_article_after,
   match_preposition_article_contraction, match_compact_preposition_article,
   match_compact_definite_article, plus special article branches embedded in
   correct_text_rich.

4. Function-phrase decisions:
   min/minn, ma/ma'/m', ta/ta', xi/x', and other phrase-specific branches.

5. Number phrases:
   _number_phrase_payload chooses a phrase independently.

6. Grammar engine:
   GrammarFinding objects can rewrite already selected surfaces, including verb
   chains, agreement, articles, and contractions.

7. Ambiguity pipeline:
   ambiguity_choices generates/ranks again; _finalize_ambiguity_choices and
   _clean_visible_choices_for_token filter or reorder again.

8. Quote/English branches:
   current quote handling emits inner text and article prefixes independently.

9. Final rich-text stages:
   capitalization, punctuation, article-tail repair, preferred apostrophe
   choices, recognition, meanings, and unrecognized state can be computed from
   different intermediate identities.

This explains why a candidate can be generated correctly, lose to another path,
be restored by a guard, then still carry the wrong choices, meaning, or squiggle.


8. PROPOSED IMMUTABLE SCHEMAS
=============================

CandidateRecord
---------------

  candidate_id: stable request-local id
  source_span: (start, end)
  source_text: exact bytes/text for that span
  source_token_ids: tuple
  normalized_input: string
  surface: candidate output before final case/punctuation
  normalized_surface: string
  generators: tuple of source identifiers
  reasons: tuple of structured reason codes
  edit_operations: tuple of typed operations
  edit_distance: numeric
  orthographic_score: numeric
  dictionary_records: immutable tuple
  pos_tags: immutable set
  verb_records: immutable tuple containing lemma/root/form/tense/person/number
  suffix_analysis: base + DO + IDO + DO_IDO + negative marker
  noun_analysis: gender/number/collective/paucal
  possessive_analysis: base/person/number
  article_analysis: typed prefix/canonical prefix/tail/assimilation/governor
  numeral_analysis: value/short-long/required noun class
  lexical_flags: name/place/demonym/English/protected
  quote_protected: bool
  apertium_analyses: immutable tuple
  hard_guard_results: tuple of pass/fail records with reason codes
  deterministic_rules: tuple of rule ids and priorities
  corpus_evidence: structured component record
  bertu_evidence: structured score record
  selection_events: immutable tuple of accepted/rejected/overwritten events

CandidateRecord must not contain a mutable "winner" flag. The selector returns a
separate SelectionDecision.

ContextRecord
-------------

  request_id
  sentence_id
  token_index
  source_span
  source_token_ids
  previous_two_selected_lexical_tokens
  next_conservatively_normalized_token
  previous_sentence_tail (bounded and optional)
  sentence_boundaries
  protected_span_boundaries
  punctuation_before/after
  capitalization_context
  preceding_governing_candidate ids
  request ambiguity count and remaining model budgets

CorpusEvidence
--------------

  mode: off/shadow/active
  available
  fallback_reason
  unigram
  left_bigram
  right_bigram
  trigram
  total_before_cap
  total_after_cap
  cache_hit
  elapsed_ms

BertuEvidence
-------------

  mode: off/shadow/active
  model/version/device
  available/load_status/fallback_reason
  complete_candidate_score
  normalized_score
  winner/runner_up/margin
  tokenizer span mapping
  candidate_subword_count
  cache_hit
  elapsed_ms

SelectionDecision
-----------------

  selected_candidate_id
  surviving_candidate_ids
  rejected_candidate_ids and reasons
  deciding_stage
  deterministic_margin/corpus_margin/BERTu_margin
  model_would_change_baseline flags
  later overwrite attempts (logged and rejected)

RenderedToken
-------------

  SelectionDecision is the only input for lexical identity.
  Z may realize case, punctuation, hyphen/apostrophe surface, and permitted
  i-/j-/u- context, but may not change the selected lemma, suffix analysis, or
  article analysis. Correction, choices, meaning, recognition, and squiggle all
  reference the same selected candidate id.

10. RISKS AND UNRESOLVED POLICY QUESTIONS
=========================================

1. niehdu is genuinely dictionary-valid:

     nieħdu: F1 MPERF-1P, "we take/catch/overcome"
     niehdu: F3 IMP-2P and PERF-3P, "cause to moan"

   Automatically rewriting standalone niehdu to nieħdu contradicts the prompt's
   hard rule that exact valid morphology cannot be replaced. Recommended policy:
   preserve standalone exact niehdu, offer nieħdu with meanings, and permit a
   context selector to choose nieħdu only with a strong margin in contexts such
   as "konna niehdu gost". User confirmation is required if standalone frequency
   should override valid rare morphology.

2. departiment versus dipartiment:

   fixednouns.dic contains dipartiment, not departiment. The current output
   Dan id-dipartiment is dictionary-backed, while the prompt requests
   Dan id-departiment. The demonstrative/article structure is correct either
   way; the canonical lemma needs confirmation.

3. lil kulħadd:

   The prompt expects bare lil kulħadd, while current article logic produces
   lill-kulħadd. The bounded linguistic rule proposed here treats kulħadd as a
   pronoun/non-article target and preserves lil. This should be confirmed as the
   general policy for lil + pronoun.

4. Quote protection is an intentional behavior migration. Existing tests and
   current UI behavior strip quote marks. The new rule protects them exactly,
   including misspellings, and blocks article fusion across the protected span.

5. Current results can depend on request-local cache order. l'ammont reaches
   l-ammont if Phase X populates the cache first, but a clean direct path returns
   l'ammont through an earlier POS-based guard. The authoritative selector must
   remove this order dependence.

6. The working tree contains substantial uncommitted user/Codex work and tracked
   generated bytecode. Implementation must preserve those edits and avoid
   accidentally committing pyc files.

7. BERTu can materially increase Cloud Run startup memory and cold latency.
   It must remain lazy and off/shadow by default until measured on the actual
   deployment configuration.

8. Full-candidate pseudo-log-likelihood is more accurate than first-subword
   scoring but costs multiple model passes. Strict candidate/call/time budgets
   and caching are mandatory.

9. Corpus absence must remain neutral. Rare correct morphology must not lose
   merely because it is absent from Korpus Malti.

10. The source and attached reports contain visible mojibake in some paths or
    terminal renderings. Encoding must be audited separately from linguistic
    behavior so repair scripts do not alter valid Maltese text.


11. PHASE 0 CONCLUSION
======================

The immediate blocker is architectural, not model quality. The required cases
do not reach CandidateEvidence, corpus, or BERTu. Enabling either model now would
leave most current selectors untouched and could add a further competing winner.

The safe order is:

  freeze corrected tests
  -> protect source spans
  -> repair deterministic morphology/structure
  -> unify candidate identity and selection
  -> pass real context to corpus in shadow mode
  -> add bounded, offset-aligned, complete-candidate BERTu shadow evidence
  -> measure before activation

The corrected suffix requirement is final for implementation:

  jilbsuwha  -> jilbsuha
  illibsuwha -> ilibbsuha

Ilibsuha must never be accepted as the target.
